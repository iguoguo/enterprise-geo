# 分册07｜落地推进与反馈迭代操作指南

> 配套《企业 GEO 优化架构性方案》第十/十一章「落地路径 + 反馈回流闭环」
> 定位：把整套方案连成"从进场到事实持续"的实施节奏、角色分工与项目推进方法。

---

## 一、总体推进路线（分阶段）

```
阶段0  进场与诊断    建立基线 → 确定优先级
阶段1  基地建设    知识底座 + 关键词/受众 + 术语表
阶段2  内容生产    首批高优先级内容 + 分发
阶段3  官网落地    技术体检 + 结构化 + 面向Agent可消费
阶段4  度量与回流    周期性度量、归因、纠偏、纳入迭代
```

> 分册间的依赖：01诊断 → 02策略/03底座 → 04生产/05分发 → 06度量，官网技术(08)全程支撑。可用"分册依赖图"做项目排期。

---

## 二、阶段 0：进场与诊断（第 0-1 周）

- 跑分册01 现状诊断，产出基线报告；
- 产出覆盖缺口与负面清单 → 作为首批选题与纠偏输入；
- 定义范围与优先级（可先聚焦高价值核心词，不贪大）。

**验收物**：《企业 GEO 现状基线报告》+ 首批出手缺口清单。

---

## 三、阶段 1：基地建设（第 2-4 周）

- 建知识底座文档树并导入存量资料（分册03）；
- 定受众画像与关键词语义地图、术语表与作者人设（分册02）；
- 与现状诊断、官网技术分层对齐。

**验收物**：知识底座可检索、关键词语义地图可用、术语表共享。

---

## 四、阶段 2：首批内容与分发（第 4-8 周）

- 按分册04 生产首批高优先级内容（权威综述/对比/FAQ/案例）；
- 按分册05 发布到渠道矩阵，回链官网，记发布台账；
- 官网技术分册同步落地结构性(Schema) 与面向Agent可消费文件(llms/robots 等)。

**验收物**：首批内容上线+多渠道发布+官网技术基线达标。

---

## 五、阶段 3：官网技术落地（可与阶段2并行）

- 做官网技术体检（抓取/理解/信任/消费/Agent五层）；
- 落地结构化数据、权威页、FAQ、纯文本视图、llms.txt、robots 分级；
- 可对照《官网GEO优化技术方案》与《官网AI-Agent文件编制指南》执行。

**验收物**：官网可抓取、可理解、可信任、可消费、面向Agent可调用。

---

## 六、阶段 4：度量与迭代（持续）

- 每 2 周/每月按分册06 跑标准采样，更新度量台账；
- 归因"动作→指标"，权重的调整；
- 负面/口径全处理，回流纠偏到内容与底座；
- 复盘输出下一步动作 → 回到阶段2/3 迭代。

---

## 七、角色与分工（职责矩阵）

| 角色 | 职责 | 负责分册 |
|------|------|----------|
| 负责人/Owner | 目标、资源、优先级、复盘 | 全部 |
| 诊断/分析 | 探测集、采样、基线 | 分册01 |
| 策略/内容策划 | 关键词、受众、选题、审核 | 分册02、04 |
| 知识管理 | 底座、来源、口径、健康度 | 分册03 |
| 渠道/运营 | 分发、第三方引用、台账 | 分册05 |
| 度量/质控 | 指标、归因、风险治理 | 分册06 |
| 官网技术 | 官网技术+Agent可消费落地 | 官网技术分册+AI-Agent分册 |

---

## 八、反馈回流闭环的操作实现

- **事实回流**：内容勘误、用户真实答疑 → 更新知识底座；
- **口径回流**：发现"同实异述" → 更新术语表/单一事实源；
- **选题回流**：客服/评论区/问答的新问题 → 进选题积压表；
- **数据回流**：度量发现覆盖缺口与负面 → 转内容与分发；
- **始终从底座出、不断回写底座**——保证"这次是基座，下次更好"。

---

## 九、项目管理模板（周报骨架）

每期周报应包含：
1. 本期动作（内容/技术/分发/纠偏清单）；
2. 度量快照（V/P/引用率/负面/缺口 较上期）；
3. 归因结论（哪个动作带来变化）；
4. 风险与待决；
5. 下周动作与负责人。
