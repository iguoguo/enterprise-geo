# 企业 GEO 优化架构性方案

**面向生成式搜索引擎的体系化、可复制的企业增长方法论**

> 适用范围：制造业、医疗健康、教育、本地生活、B2B 服务、电商等各类企业
> 关键定位：**架构性**——提供分层体系而非单点技巧；**普适性**——方法论与行业无关，可用一张模板框架适配任何企业与场景

## 一、范式转变：从 SEO 到 GEO

当越来越多用户在生成式引擎（AI 搜索/对话式问答/智能助手）里"找答案"，企业内容竞争的核心诉求发生了根本性跃迁：

| 维度 | 传统 SEO | GEO（生成式引擎优化） |
|------|----------|------------------------|
| 目标 | 排名靠前 | 被 AI 理解、信任、引用、推荐 |
| 一件内容 | 网页/关键词 | 可被验证的知识型内容 + 结构化出处 |
| 优化对象 | 搜索引擎爬虫 | 大模型的检索、理解与生成链路 |
| 内容形态 | 信息堆砌 | 有依据、可回溯、口径一致、覆盖完整 |
| 度量 | 排名 / 点击 | 被引用次数 / 被推荐频次 / 品牌可见度 |
| 护城河 | 域名权重 / 外链 | 知识底座的质量与回流速度 |

**核心判断**：GEO 竞争的胜负手，不在某一个热搜词，而在于企业能否建立起一套 **"以知识为底座、可被生成引擎信任的体系"**。这也决定了 GEO 必须作为一项**架构级工程**来建设，而非内容运营人员的临时任务。

## 二、第一步：企业 GEO 现状诊断

GEO 方案落地的前置动作、也是**整个方案的第 0 步**：在动手建设任何能力之前，先针对**该企业自身**做一次 GEO 现状体检，摸清"企业当下在生成式引擎里是什么位置"，再据此决定优化方向、优先级与资源投入。没有基线，后续一切优化无法度量、无法归因。

### 2.1 诊断定位与目标

现状诊断回答三个问题：

- **现在在哪**：企业品牌、产品、核心关键词在主流生成引擎（豆包、DeepSeek、文心一言及各类智能助手）中的真实表现。
- **和谁差**：相对主要竞品、行业基线的可见度差距。
- **往哪打**：暴露出的覆盖缺口、负面与失实点、被引用但不可溯源的问题，作为方案各层设计的落点。

诊断产出是一份**企业 GEO 现状基线报告**，既是方案的起点，也是后期度量层"改善了多少"的对照基准。

### 2.2 诊断维度：企业在 AI 中的表现

从五个维度刻画"这家企业在生成式引擎里"的全貌：

| 维度 | 含义 | 典型问题 |
|------|------|----------|
| 可见度 / 覆盖率 | 企业、品牌、关键词被生成引擎提及的比例 | 是否在大部分相关提问中"隐形" |
| 占位与引用 | 被引用/推荐时的占位等级（被推荐 / 并列提及 / 仅出现 / 完全不出现） | 是否只是"被顺带提到"而非"被推荐" |
| 情感与倾向 | 被提及时的正/中性/负面倾向，负面信息覆盖度 | 是否有失实、陈旧或负面内容被 AI 采信 |
| 可信与可溯源 | 被引用是否带来源、来源是否可用且指向权威/官网 | 是否被引用却无法溯源到官网，或引用错误来源 |
| 覆盖缺口 | 企业应占位却未占位的关键词/提问场景 | 核心"痛点词"无内容覆盖，机会被竞品占据 |

### 2.3 诊断方法：如何测出真实现状

- **批量探测（核心手段）**：将企业关键词库 × 标准提问句式组织成"探测集"，定时向主流生成引擎批量发起提问采样，记录每一次"提到 or 不提 / 引用 or 不引 / 来源指向哪"。
- **结构化统计**：对采样结果计算占位率、引用率、来源可用率、负面覆盖度、情感得分；数据可横纵对比（不同引擎、不同时段、不同提问变体）。
- **官网/来源侧核查**：检查官网是否被正常爬取与理解（收录、结构化数据、sitemap 覆盖）、哪些来源正在为企业在 AI 中被引用背书。
- **竞品与基线对标**：对竞品跑同一个探测集，量化差距，设定可追赶的基准线。
- **口径与失实排查**：逐条核查 AI 输出中与本企业相关的事实、数据、历史表述是否准确，识别需要澄清与修正的点。

### 2.4 关键诊断指标（基线清单）

| 指标 | 定义 | 意义 |
|------|------|------|
| 可见度 V | 相关提问中品牌被提及的比例 | 是否"被看见" |
| 占位率 P | 被直接推荐/列为首选的占比 | 是否"被信任优先" |
| 引用率 | 被引用时带可溯源的来源占比 | 是否"可持续被采用" |
| 来源可用率 | 引用来源可打开、指向权威/官网的占比 | 来源基建是否扎实 |
| 负面覆盖度 | 负面/失实表述出现的提问占比 | 声誉风险水位 |
| 覆盖缺口 | 应占位却未占位的关键词数 | 内容机会与发力点 |

### 2.5 诊断输出与定位

诊断完成后形成 **《企业 GEO 现状基线报告》**，包含：现状画像、差值清单（对竞品/基线）、覆盖缺口矩阵、负面与失实清单、官网/来源基建体检结果，以及**按优先级排布的优化建议**。

该报告向下驱动——

- **战略层**：基于覆盖缺口与词库，校准关键词地图与内容目标。
- **知识底座层**：针对缺口径、被失实引用的知识点，先补知识与来源。
- **内容与分发层**：把缺口与负面清单转成第一批选题与纠偏内容。
- **度量层**：以本次基线作为后续"改善了多少"的对照基准。

至此，企业 GEO 现状诊断作为第一步"量出当下的位置"，为整个架构的落地拉开序幕。

## 三、总体架构：五层 + 一闭环

企业 GEO 优化体系可拆解为 **五个层次 + 一个贯穿性闭环**，官网既是最关键的分发落地（技术是底座、内容是骨架），也是全体系被生成引擎"看见与信任"的主阵地。

```
┌─────────────────────────────────────────────────────────────┐
│  ⑤ 度量与治理层   引用监测 / 归因分析 / 合规审计 / 迭代治理      │
├─────────────────────────────────────────────────────────────┤
│  ④ 分发与触达层   多渠道发布 / 结构化标记(结构化数据/AI情报)     │
├─────────────────────────────────────────────────────────────┤
│  ③ 内容生产层     选题蒸馏 / 有据创作 / 面向AI的优化 / 审核       │
├─────────────────────────────────────────────────────────────┤
│  ② 数据与知识底座  知识沉淀 / 知识图谱 / 来源追溯 / 版本一致      │
├─────────────────────────────────────────────────────────────┤
│  ① 战略与策略层   受众画像 / 关键词体系 / 内容目标 / 人设          │
└─────────────────────────────────────────────────────────────┘
        ◀──────────── 官网落点：技术底座 + 内容骨架 ───────────▶
                      ▲                          │
                      └────恒 期 反 馈 与 回 流 ──┘
```

- **自上而下是"指导"**：战略定方向，底座供素材，生产产内容，分发被看见，度量作反馈。
- **自下而上是"支撑"**：每下一层都要求上一层"有据可依"。
- **官网是纵贯所有分发的"主落点"**：技术层让官网可被爬取、理解、信任；内容层让官网成为被引用的权威来源；度量层把官网的引用表现回流到战略与知识。
- **贯穿着一个闭环**：`战略 → 知识 → 内容 → 分发 → 度量 → 回流到战略与知识`——内容可验证、可归因、可持续迭代。

### 设计原则

1. **知识驱动**：一切内容有真实出处，被生成引擎信任的前提是可被验证。
2. **口径一致**：同一事实在不同文章/渠道中表述一致，避免被引擎判定为矛盾。
3. **覆盖完整**：关键主题的知识缺口用蒸馏识别、用创作补齐。
4. **可追溯、可审计**：每个观点可回溯到来源，满足合规与信任要求。
5. **闭环演化**：度量结果回流，驱动战略与知识不断生长，而非一次性的项目。

## 四、第一层：战略与策略层

解决"为什么做、服务谁、朝哪个方向做"的问题。这一层不产出内容，但决定内容的方向和质量上限。

### 4.1 受众画像与人群分层
- 定义目标人群（技术决策者、采购、患者、C 端消费者……），抽象出职业、技能水平、关注点、信息获取习惯、典型疑问。
- 分层满足：**决策链全覆盖**（影响者 → 评估者 → 决策者）与 **旅程全覆盖**（认知 → 评估 → 决策 → 复购/扩散）。
- 输出：一份可持续复用、可按需调整的人群画像库。

### 4.2 关键词与语义地图
- 建立**主题域 → 关键词组 → 长尾疑问**三层结构。
- 每个关键词关联明确目标（品牌曝光 / 获客 / 信任背书 / 防误解）。
- 语义地图需持续**跟踪生成引擎中用户提问的新表述**，识别内容机会与缺口。

### 4.3 内容目标与场景矩阵
| 场景 | 典型目标 | 内容侧重 |
|------|----------|----------|
| 品牌认知 | 被 AI 推荐为权威来源 | 权威综述、行业观点 |
| 潜在获客 | 被 AI 引用为解决方案 | 对比分析、案例研究、选型指南 |
| 交易转化 | 被 AI 推荐为可下单对象 | 产品详情、客户证言、FAQ |
| 声誉管理 | 纠正误解、负面澄清 | 澄清声明、事实核查、官方口径 |
| 生态协同 | 被生态伙伴引用 | 白皮书、标准、开放文档 |

### 4.4 作者人设与品牌口径
- 定义"以谁的口吻对外发声"，统一品牌人格，避免多作者口径漂移。
- 建立**品牌术语表**（产品名、专有名词、禁止表述），作为所有层级的约束输入。

## 五、第二层：数据与知识底座

GEO 的"地基"。生成引擎信任的根基是**可验证的事实**，这一层负责把企业散落的资料沉淀为高可信、可追溯、组织良好的知识体系。

### 5.1 知识沉淀与体系化
- 收集分散文档（白皮书、章程、产品手册、病历规范、FAQ、历史内容）形成**文档树**。
- 维护文档的质量标准：准确、及时、口径统一、结构组织良好。
- 建立**知识图谱**：把知识条目组织成有层级、有关联、被标记来源的结构，支撑后续"按图创作"。

### 5.2 来源追溯与可信
- 每个知识条目保留**来源与版本**，构成"事实-出处-版本"三要素。
- 支持从产出内容**反查依据**，这也是与生成引擎"可验证"诉求对齐的关键。
- 建立变更历史，避免知识被随意改动导致口径漂移。

### 5.3 一致性与去重
- 制定同名事实的**单一事实源（Single Source of Truth）**，内容生产以底座为准，不允许各写各的。
- 识别并消除重复、冲突、过期的知识条目。

### 5.4 扩展与共享
- 知识底座应能被多个内容项目、多个业务线共享，形成**企业级资产**，而非某个团队的私有库存。
- 供外部可读的部分（白皮书摘要、公开 FAQ）与内部全量（含敏感）分权隔离。

## 六、第三层：内容生产层

把知识底座转化为"可被生成引擎引用"的内容。核心循环为 **蒸馏 → 创作 → 优化 → 审核**。

### 6.1 选题蒸馏（方向涌现）
- 结合**目标 + 关键词体系 + 受众画像 + 知识图谱现状**，自动分析并生成选题建议。
- 通过"接受 / 修改 / 忽略"人工拍板，保证方向受控。
- 支持**上下文感知**：在编辑某文时，基于当前片段提供针对性、有承接的选题。
- 选题库可手动创建、按类型/字数筛选，成为可排期的内容管道。

### 6.2 有据创作（事实可信）
- 内容以**知识图谱为素材核心**，从绑定条目中提取事实、概念、关联，组织成结构完整文章。
- 每个观点**可追溯**到具体知识条目，杜绝凭空编造。
- 支持**批量生成**：一次选择多组选题，规模化产出，适合扩量打基础。

### 6.3 面向 AI 的优化（可被理解）
- 自动优化**标题、描述、结构**，增强被生成引擎抽取、转述、引用的概率。
- 优化要点：清晰的段落结构、明确的实体与事实陈述、规范的引用/来源标注、对常见"提问句式"的覆盖。
- 注意：优化不等于堆砌关键词或编造，仍以事实和可读性为底线。

### 6.4 人工审核（质量守门）
- 对生成内容进行事实核对、口径校验、品牌合规审核，再行发布。
- 审核通过与否都回流成经验，反哺蒸馏与优化规则。

---

## 七、第四层：分发与触达层

解决"内容被生成引擎看见与引用"的最后一步：把合适的内容发布到合适的位置，并增强机器可读性。

### 7.1 多渠道发布矩阵
| 渠道 | 作用 | 优先级 |
|------|------|--------|
| 官网/独立站 | SEMM（生成引擎）引用主力 | 高 |
| 公众号/内容平台 | 覆盖国内 AI 搜索语料 | 高 |
| 海外站点/知识平台 | 覆盖全球引擎 | 中 |
| 第三方权威平台 | 借势可信背书 | 视行业 |
| 结构化知识文档 | 直接喂养 API/智能体 | 高 |

### 7.2 结构化与机器可读
- 输出并维护**结构化数据 / 机器可读接口**，让内容不仅给人看，也可被 API、智能体、爬虫直接消费。
- 关键内容提供**规范的元数据、来源链接、更新日期**，强化信任信号。

### 7.3 发布即留痕
- 每次发布记录渠道、URL、版本、发布时间，为度量层提供归因基础。
- 发布后的内容可选择回存为文档，便于统一管理。

## 八、官网技术&内容优化层（主落点）

官网是 GEO 体系被生成引擎"看见、理解、信任、引用"的**第一主阵地**。它的优化分两条主线：**技术是底座**（决定能否被爬取与读懂），**内容是骨架**（决定是否值得被引用）。

### 8.1 官网技术优化（底座：让引擎爬得动、读得懂）

解决"生成引擎能否顺利抓取并正确理解官网"这一前提问题。

**可抓取（Crawlability）**
- 合理的**站点架构**：扁平、清晰的目录层级与内部链接，关键页面 3 跳内可达。
- **Sitemap**：覆盖全站核心页面，随内容更新同步维护并提交。
- **Robots / 抓取友好**：不误屏蔽可公开内容，动态渲染对爬虫可见（SSR/预渲染优先）。
- **性能**：首屏与页面速度达标（生成引擎的抓取与评价均偏好稳定快速站点）。

**可理解（Understandability）**
- **结构化标记（Schema / 结构化数据）**：为产品、FAQ、企业信息、文章、评分等实体标注规范语义，让引擎不再"猜"而是"读"。
- 语义与实体：明确的标题层级、实体名称、事实陈述，避免模糊表达。
- 唯一的权威 URL 与规范化（canonical）设置，避免重复内容稀释可信度。

**可信任（Trust & Authority）**
- HTTPS 与站点安全、明确的企业信息/备案、稳定的联系与资质页面。
- 更新日期、作者/来源标注，让内容"新鲜且可验证"。
- 全网一致的口径，避免不同页面自相矛盾。

### 8.2 官网内容优化（骨架：让引擎值得引用）

官网页面不只为满足浏览，更要**成为可被生成引擎引用的事实与权威来源**。

**页面级内容组织**
- 每类核心主题设一个"权威页（Hub）"聚合事实与全景，向外辐射子页/长尾问答页。
- 老牌核心页（方案、产品、FAQ）承载**企业关键事实**，口径与知识底座强一致。
- 面向"用户真实提问句式"组织内容（疑问、比较、选型、流程问答），命中生成引擎抽取倾向。

**引用友好**
- 关键数据、案例、资质**给出可核验出处**，便于被理解为事实来源。
- 页面提供规范的作者、来源、日期元数据，增强信任信号。
- 优质内容与官网结构呼应知识图谱，让"蒸馏→创作→官网"形成同源链路。

**官网内容与知识底座联动**
- 官网页作为知识底座**对接生成引擎的出口窗口**：知识产生的文章择优上官网，官网的自然流量/信任反哺知识链路。
- 官网的常见问答/结构数据同时可预览给 API 与智能体消费，覆盖"人搜+机读"两套语料。

### 8.3 官网技术 / 内容检查清单（落地自查）

| 维度 | 自查项 |
|------|--------|
| 抓取 | 关键页可达、Sitemap 完整、不误屏蔽、无重复 URL |
| 理解 | 结构化标记就绪、标题层级规范、canonical 正确 |
| 信任 | HTTPS、企业信息完整、日期与作者标注、口径一致 |
| 内容 | 核心主题有权威页、覆盖提问句式、关键事实可溯源 |
| 联动 | 官网知识同源、FAQ/结构数据可被 API/智能体消费 |

> **衔接提示**：官网向"AI Agent 主动探测/调用"层面的落地细节（LLMs.txt、robots.txt 挖虫分级、纯净正文直取、段落锚点、开放接口等），见配套的《官网 GEO 优化技术方案》第六章「面向 AI Agent 的官网可消费性」。

## 九、第五层：度量与治理层

GEO 的"仪表盘与方向盘"，确保投入可衡量、可归因、可持续。

### 9.1 关键指标体系
- **可见度**：在主流生成引擎中被提及/推荐的次数与覆盖率。
- **引用质量**：被引用时是否为正面、事实、带来源引用。
- **信任度**：口径一致率、来源可用率、错误引用率。
- **转化**：被引用的相关线索/流量/成交的下游转化。
- **健康度**：知识底座的新鲜度、缺口数、冗余/冲突数。

### 9.2 归因分析
- 将"被引用"归因到**具体内容 → 选题 → 知识条目 → 关键词**，找到真正贡献价值的要素。
- 基于归因结果，决定内容的增补、修改或下架。

### 9.3 合规与审计
- 医药、金融、教育等强监管行业**优先治理**：禁止夸大、疗效/收益承诺、未经验证声明。
- 建立**引用可倒查**机制：任何对外内容都可回溯到被许可的来源。
- 定期审计口语一致性与内容陈旧度，淘汰过期信息。

### 9.4 迭代治理
- 度量结果周期性回流到**战略层**（调整关键词/目标）与**知识底座**（补齐缺口、更新过时事实）。
- 形成"种子—收成—再播种"的持续演化，杜绝一次性建完后放着不管。

## 十、恒期反馈与回流闭环

闭环是整套架构的"发动机"。没有回流，GEO 就会退化为一次性的内容项目。

```
知识底座 ──蒸馏──▶ 选题 ──创作──▶ 有据文章 ──优化──▶ 可被AI引用
   ▲                                                        │
   └──────────── 新知识回流 ◀──── 度量结果 ◀──── 分发与监测 ─┘
```

- **内容 → 知识**：文章中产出的新观点、补充数据、打磨后的表述，回流沉淀为知识，反哺下一轮。
- **度量 → 战略**：引用表现反哺关键词与目标设定，让方向持续贴合真实需求。
- **度量 → 底座**：识别知识缺口与陈旧项，驱动知识库同步更新。

## 十一、落地路径：从启动到体系化

> 普适性体现在：阶段不变，各阶段的具体动作可按行业与规模伸缩。

| 阶段 | 周期（参考） | 核心任务 | 关键产出 |
|------|--------------|----------|----------|
| 0 基础检查+现状诊断 | 第 1–2 周 | 官网基础体检（ICP 备案/HTTPS、robots/sitemap、首页元信息、身份识别）；企业 GEO 现状体检（AI 中可见度/占位/引用/负面/缺口）、竞品对标 | 基础检查报告 + 现状基线报告 + 优化优先级 |
| 1 官网地基层 | 第 2–4 周 | 身份/定位落地、Schema、robots/sitemap 就绪、llms.txt 与 AI 挖虫分级、官网服务子页骨架（**与知识底座并行**） | 官网可被抓取、可理解、可信任、可被 Agent 引用 |
| 2 知识+策略 | 第 2–5 周 | 资料归集、建文档树、补知识图谱、定来源规范；定义受众、建关键词地图、术语表（与阶段 1 并行） | 可追溯知识库 + 内容方向库 |
| 3 生产试跑 | 第 5–8 周 | 蒸馏首批选题、小批量创作、建立审核流程 | 第一批可验证内容 |
| 4 规模化发布 | 第 8–12 周 | 批量生成优化、多渠道发布、官网权威页与 FAQ 上线、结构化导出 | 多平台可见度 + 官网引用来源 |
| 5 度量与回流 | 长期 | 建指标、归因、审计、官网口径维护、回流知识底座 | 可持续增长飞轮 |

**成功关键**：GEO 的天花板由**知识底座质量**决定，而非文章数量。知识越准确、及时、组织越好，蒸馏出的选题和生成的内容越可信，越可能被生成引擎引用。

## 十二、普适性适配：一张框架套用所有情形

### 12.1 按行业
| 行业 | 重点策略 | 风险关注 |
|------|----------|----------|
| 医疗健康 | 科普+权威出处+就医引导 | 疗效承诺、广告法、隐私 |
| 制造业/B2B | 技术方案+案例+选型指南 | 数据保密、反竞争 |
| 教育 | 知识体系+方法+招生转化 | 培训承诺、资质宣传 |
| 本地生活 | 场景意图+真实评价+到店转化 | 虚假评价、真实性 |
| 金融 | 投教+产品信息+风险揭示 | 收益承诺、消保合规 |

### 12.2 按规模
- **中小型**：先建最小可行闭环（轻量知识库 → 每月固定选题 → 单渠道发布 → 月度复盘），用 1 个业务线验证后扩展。
- **大型/集团**：多业务线共享企业级知识底座，建设专职 GEO 团队与治理委员会，分层分级授权。

### 12.3 按技术底座
- 本方案为**能力要求**层面，不绑定具体工具。企业可自建，也可依托具备"蒸馏-创作-优化-发布-回流"能力的内容引擎（如 2Ryun GEO Engine）与知识库协同落地。
- 技术选型需满足：知识可追溯、来源可倒查、内容可批量、发布可暗痕、度量可回流。

## 十三、典型风险与应对

| 风险 | 表现 | 应对 |
|------|------|------|
| 内容空洞无依据 | 生成引擎不引用 | 强制知识底座驱动、来源可追溯 |
| 口径漂移 | 多作者/多版本表述矛盾 | 单一事实源 + 术语表 + 版本审计 |
| 合规违规 | 夸大、承诺、误导 | 强监管行业优先治理、引用倒查 |
| 一次性工程 | 建完即停、无回流 | 度量回流闭环、常态运营制度 |
| 知识陈旧 | 老信息被引用酿错 | 定期健康度审计、过期下架 |
| 官网技术缺陷 | 内容无法被爬取/读懂 | 结构化标记、站点架构与抓取优化 |
| 官网口径不一 | 各页面相互矛盾致不信任 | 官网与知识底座同源、术语表约束 |
| 数据安全 | 敏感信息外泄 | 内外分权、发布前审核 |

## 十四、结语

企业 GEO 优化不是一项"运营动作"，而是一套**以知识为底座、以生成为链路、以回流为动力的架构级工程**。它把竞争从"抢一个排名"提升到"建一个被信任的知识体系"：

- **业绩靠内容，内容靠知识，知识靠回流**。
- 谁的知识底座更扎实、闭环跑得更勤，谁的内容就越可能被生成式引擎理解、信任与引用。
- 这套架构的价值在于**可复制**：授人以框架，企业按自身行业、规模、资源在此骨架上"生长"出自己的 GEO，而不是照搬一招一式的操作。

最终，企业真正值钱的不是散落的文章，而是那条**持续沉淀、验证、回流、滚雪球式增长的知识主线**——这正是企业 GEO 优化的本质，也是本方案想交付的核心。

## 附录：企业 GEO 共性问题自查

> 跨行业、跨规模的**高频共性病灶**。新企业接手时逐条自查是否命中；命中项优先处理——这些通常是"免费午餐"：单点修复、收益明显。

| # | 共性问题 | 症状（在 AI 里的表现） | 根因 | 处置动作 |
|---|----------|------------------------|------|----------|
| 1 | **官网基础未就绪** | 引擎判官网为"空站/备用域名"、无法绑定身份 | ICP 未备案、robots/sitemap 缺失、首页无元信息 | 先查先修，见官网地基层 |
| 2 | **身份叙事错位** | AI 把主业认成副线/同名他司（如"服务商被认成素材站"） | 官网定位不清、多线业务未讲明关系 | 建身份澄清页 + Organization/ProfessionalService Schema |
| 3 | **案例匿名化浪费背书** | 强案例没变成可信事实节点，AI 不可核验 | 未授权、不敢点名、无结构化解法案例 | 实名分级，能实名则 StructuredData 化 |
| 4 | **知识底座单薄** | 内容无出处、被引用却不可溯源 | 资料散落、未沉淀、无来源追溯 | 见知识底座层 |
| 5 | **口径不一致** | "参保 0 人""价格漂移"等被引擎当风险提示 | 多渠道/多版本表述打架 | 单一事实源 + 术语表 + 口径体检 |
| 6 | **覆盖缺口** | 应占位的关键问题 AI 完全不提，机会让给竞品 | 只做品牌词、没做长尾/业务词 | 现状诊断画缺口矩阵，按 P0 补 |
| 7 | **能力数字不带出处** | 关键业绩/数据被引用却无法反查 | 无版本时间戳、无核验页 | 关键数据标时间/口径，官网可核验 |

> 处置时与快速启动表的 ①③ 步联动：命中项大多在"官网地基层 + 现状诊断 + 知识底座"三个阶段即可消化。
