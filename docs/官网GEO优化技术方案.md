# 官网 GEO 优化技术方案

**面向生成式搜索引擎的官网技术落地手册**

> 配套文档：可与《企业 GEO 优化架构性方案》第七章衔接使用
> 定位：聚焦**官网**这一主落点，从技术实施层面给出可执行的优化动作、结构化标记方案与检查清单，不重复整个企业架构

---

## 一、方案目标与适用范围

官网是生成式引擎（AI 搜索/对话问答/智能助手）抓取、理解、信任并引用企业信息的**第一主阵地**。本方案围绕官网回答三个技术问题：

1. **能不能被抓到** —— 可抓取性（Crawlability）
2. **能不能被读懂** —— 可理解性（Understandability），含结构化数据
3. **值不值得被引用** —— 可信度与可溯源（Trust & Authority）

**技术路线总览**：

```
官网技术底座
 ├─ 可抓取层：站点架构 / SSR与渲染 / Sitemap / Robots / 性能
 ├─ 可理解层：语义化HTML / 结构化数据(JSON-LD+Schema.org) / canonical / 内链
 ├─ 可信任层：HTTPS / 企业信息与资质 / 更新与作者标注 / 口径一致
 ├─ 可消费层：FAQ/API/知识文档对接生成引擎(人搜+机读双语料)
 └─ 面向AI Agent层：LLMs.txt / AI挖虫策略 / 纯净直取 / 段落锚点 / 开放接口
```

---

## 二、可抓取层：让引擎爬得动

### 2.1 站点架构
- **扁平化层级**：目录深度原则不超过 3 层，关键页面 3 跳内可达；避免深埋孤儿页。
- **唯一权威 URL**：每页只有一个目标 URL，区分 `www`/非 `www`、`http`/`https`，站点内统一绝对路径。
- **内部链接环**：核心权威页（Hub 页）指入所有子页/长尾页，子页反向链接回 Hub，形成可控链接权重传导。
- **面包屑导航**：提供层级面包屑，既利于理解也利于结构化标记（BreadcrumbList）。

### 2.2 渲染与爬取友好
- **优先 SSR/SSG**：关键内容动态渲染对爬虫可见；使用 CSR 的单页应用务必配置 SEO 友好渲染（预渲染/混合渲染），避免"空壳页面"。
- **按需加载不阻塞识别**：首屏内容应包含在初始 HTML 中，重要文本不要放在 JS 异步拉取后才出现。
- **Robots 规则审慎**：只屏蔽确需屏蔽的资源（如后台、隐私页面），**不要误屏蔽**核心内容、CSS/JS 资源；`robots.txt` 与代码规范一致。
- **Sitemap 完整**：覆盖全站核心页，随内容增删同步更新并主动提交；避免提交大量死链、重定向链。

### 2.3 性能基线
生成引擎的抓取与评价均偏好稳定、快速、可访问的站点。落地基线建议：
- 首屏加载时间（LCP）控制在合理区间，移动端优先。
- 稳定可用（返回码、可用率、无重复超时）。
- 关键资源（CSS/JS）允许爬虫顺利获取，避免因渲染卡顿导致内容识别不全。

### 2.4 技术可抓取检查
- 关键页可达、无深层/孤儿页（用站内抓取工具验证一次）。
- Sitemap 有效、Robots 未误屏蔽、无大量重复 URL/参数化重复页。

## 三、可理解层：让引擎读得懂

这一层决定生成引擎是"读懂"你的官网还是"猜"，进而影响是否引用你。

### 3.1 语义化 HTML
- 使用规范的 `h1 → h2 → h3` 标题层级，单页一个 `h1`，承载核心主题。
- 用 `<article>`、`<section>`、`<nav>`、`<aside>` 等语义标签组织区块。
- 关键实体（品牌名、产品名、服务名、人、时间）在文本中清晰陈述，避免笼统表达。

### 3.2 结构化数据（JSON-LD + Schema.org）——技术核心

用 `application/ld+json` 输出机器可读的结构化事实，让引擎"读到"而不仅是"看到"。按页面类型选用：

| 页面类型 | Schema 类型 | 关键属性示例 |
|----------|-------------|--------------|
| 企业概况 | Organization | name、logo、url、address、contactPoint、sameAs |
| 产品/服务页 | Product / Service | name、description、offers.price、brand、image |
| 文章/方案 | Article / TechArticle | headline、author、datePublished、dateModified、about |
| 问答/FAQ 页 | FAQPage | mainEntity[].Question + AcceptedAnswer |
| 教程/操作页 | HowTo | step 化的结构化步骤 |
| 本地实体（医疗/门店等） | LocalBusiness / 子类 | geo、address、openingHours、priceRange、medicalSpecialty 等 |

**要点**：
- 一条内容用一张 `@graph` 聚合多类型，避免互相矛盾的零散标记。
- `@id` 使用权威 URL 作为实体稳定标识，跨页面复用同一实体 `@id`。
- 标记内容必须与页面可见文本**一致**，不得夸大、不得造假（这是引用信任与合规的底线）。

### 3.3 canonical 与重复内容治理
- 全站设置 `rel=canonical` 指向唯一权威 URL。
- 参数化页面（排序/筛选/PCM）规范为不产生重复收录。
- 统一页面标题与描述的唯一性。

### 3.4 可理解检查
- 每类核心页是否都有对应结构化数据（用 Schema 验证工具校验无错误）。
- 标题/实体/事实表述清晰无歧义，canonical 正确无重复页。

## 四、可信任层：让引擎值得引用

生成引擎倾向于引用**来源可核验、口径一致、更新可查**的内容。

### 4.1 站点信任基建
- HTTPS 全覆盖、证书有效、无安全告警。
- 完整的企业信息与资质页：关于页、联系方式、主体信息/备案、服务资质/证照。
- 稳定的品牌一致表达（同 logo、同企业名称、同联系方式跨页统一）。

### 4.2 内容可信信号
- 每篇文章/页标注**作者、发布日期、更新日期**（与 `datePublished/dateModified` 一致）。
- 关键数据、案例、资质**给出可核验出处**，指向权威/官网原文。
- 避免夸大、绝对化、无依据承诺——尤其医药、金融、教育等强监管行业。

### 4.3 口径一致（防漂移）
- 同名事实在官网各页**单一事实源**强一致，不随文案随意改写。
- 与外部发布渠道（公众号、第三方）共用品牌术语表，避免被判定"同实异述"。

## 五、可消费层：对接"人搜 + 机读"双语料

官网内容不仅给人看，也要可被 AI 引擎、搜索爬虫、API/智能体直接消费。

### 5.1 FAQ 的内容化与结构化
- 将用户高频真实疑问整理为 FAQ 页，并为每条 FAQ 输出 `FAQPage` 结构化数据。
- 提问用"用户真实提问句式"，命中间答式场景的抽取与转述。

### 5.2 权威 Hub 页设计
- 每个核心主题设权威页（Hub）聚合事实与全景，向引擎表达"这是该主题的官方权威来源"。
- Hub 页之间、Hub 与子页之间形成可被理解的实体关联。

### 5.3 结构化知识导出
- 对需要"喂养"API/智能体的内容，输出机器可读的知识文档（结构化数据 / OpenAPI 兼容的接口 / 可消费的 JSON），让官网不止是页面。
- 保持与页面内容同源，避免"页面一套、接口另一套"。

### 5.4 监测与闭环（技术侧）
- 建立**引用探测**：对官网相关关键词×提问句式定期向各生成引擎采样，统计被提及/被引用/来源指向官网的占比。
- 监测**来源可用率**：被引用时来源是否可打开、是否指向官网、内容是否更新。
- 结果回流驱动官网的增页、改版、纠偏与结构化补全。

## 六、面向 AI Agent 的官网可消费性

前几层着眼于"搜索爬虫抓取官网"。而当用户把官网当成**可自主行动的 AI Agent 的信息源**时，Agent 会主动探测、读取、调用官网，其诉求与爬虫不同：要更少噪音、更结构化、更可精确引用。本章补充这一视角的落地动作。

### 6.1 LLMs.txt 类协议（性价比最高，强烈建议优先落地）

为 AI 挖虫定制一份"精选索引 + 官网说明书"，让 Agent 一进来就知道"该怎么读、重点在哪"。

- 维护一份机器可读的站点索引文件（如 `llms.txt` + 全文版 `llmsfull.txt`），列出核心页面 URL、一句话摘要、与更新频率。
- 它相当于给 AI 的"菜鸟导航"：Agent 可凭此直达高价值页面，而不是按 URL 海量乱爬。
- 保持与 sitemap、正文分层一致，标题与摘要精准，避免与页面不符。

### 6.2 AI 挖虫策略：robots.txt 分级与隐私开关

把"可被抓取"细分为**"可被抓取并引用"**与**"可被抓取用于训练"**两档，并在 `robots.txt` 显式声明：

- 显式列出主流 AI 挖虫（GPTBot、ClaudeBot、Google-Extended、Bingbot，以及字节·火山、阿里等国内引擎对应的 agent），逐条写明允许还是拒绝抓取/训练。
- 结合隐私与合规（如内部资料、客户数据、未公开内容）决定哪些目录对挖虫屏蔽。
- `robots.txt` 之间及字段之间避免冲突，抓取策略代码与运营口径一致。

### 6.3 纯净正文直取视图（降低噪音）

Agent 解析页面时，导航、弹窗、Cookie 横幅、图表脚本常把正文"稀释"：

- 提供**正文直取端点**（如 `?output=plain=1` 或独立纯文本视图），让 Agent 拿到的就是干净正文。
- **正文前置、关键事实靠前**：Agent 上下文有限，开头几句要能直接命中核心结论。
- 对无 JS 环境友好，正文可在无脚本下完整读取。

### 6.4 段落级引用锚点

给关键声明加**稳定锚点/id**（如 `h2/h3` 与段落 `id`），让 Agent 能引用官网"某一句"而非整页：

- 提升引用精确度与来源可用率（Agent 返回可核实的原文位置）。
- 锚点与结构化数据 `@id` 对应，增强实体可追溯。

### 6.5 开放接口与 OpenAPI 描述（进阶：强动态信息）

面向"必须实时获取"的信息（实时库存、预约、报价、价格）提供**结构化接口**，并配 `OpenAPI` / `JSON Schema` 描述，让 Agent 直接调用而非解析 HTML：

- 提供带鉴权的只读开放接口，返回与官网同源的规范 JSON。
- 接口元数据（路径、参数、返回结构、限流）可机器消费，降低 Agent 接入成本。

### 6.6 面向 Agent 的语义站点图与增量抓取

- **语义站点图**（主题簇/实体地图）帮助 Agent 理解站点结构，而非按 URL 漫爬。
- **增量抓取信号**：利用 `ETag` / `Last-Modified` 标注内容版本，减少 Agent 反复整站重抓，提升效率与稳定性。

### 6.7 AI 挖虫访问监测与提示注入防护

- 从服务器日志识别不同 AI 挖虫的抓取行为与频率，反向优化命中率与命中内容。
- **提示注入防护**：防隐藏文本、防内容污染、防恶意 prompt 诱导官网输出非官方口径，保护品牌与数据安全。

### 6.8 本章落地优先级

| 优先级 | 动作 |
|--------|------|
| 高 | LLMs.txt、robots.txt AI 挖虫分级、纯净正文直取、段落锚点 |
| 中 | AI 挖虫日志监测与纠偏、增量抓取信号 |
| 进阶 | 开放接口 + OpenAPI、语义站点图 |

## 九、常见误区与风险

| 误区/风险 | 说明 | 应对 |
|-----------|------|------|
| 结构化造假 | 标记与页面不一致、夸大 | 标记=可见文本，先用校验器审查 |
| 过度优化 | 堆 Schema/关键词、制造海量低质页 | 以真实覆盖为准，重质不重量 |
| 内容深埋 | 关键文本依赖 JS 异步，爬虫看不到 | SSR/预渲染 + 首屏直出 |
| 口径漂移 | 官网各页与外部表述矛盾 | 术语表 + 单源事实 + 版本审计 |
| 更新失联 | 标了日期却从不维护，陈旧信息被引 | 定期内容健康度审计、下架过期 |
| 合规越线 | 强监管行业过度承诺 | 医药/金融/教育优先治理、引用可倒查 |
| AI 挖虫误配 | robots.txt 误屏蔽或被用于训练 | 分级策略、按隐私/合规声明、冲突校验 |
| 提示注入 | 恶意 prompt 诱导官网输出非官方口径 | 隐藏文本防护、内容污染监测 |
| 接口与页面脱节 | 开放接口与页面口径不一致 | 同源发布、版本对齐 |

## 十、结语

官网的 GEO 技术优化不是一次性的"打标签"动作，而是一套**可抓取 → 可理解 → 可信任 → 可消费 → 面向 Agent 可自主调用**的持续工程。它的落地依赖两块：一是**技术正确**（架构、渲染、结构化数据、性能与信任基建扎实）；二是**内容同源可验证**（与知识底座/官方口径强一致，使官网成为生成引擎与 AI Agent 都愿意引用的权威来源）。

当官网做到"既能被读懂、又值得被引用、还能被 Agent 与 API 智能体直接消费与精确引用"，它就真正成为了企业 GEO 体系的**主阵地与信任支点**。
