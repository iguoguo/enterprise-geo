# 官网 GEO 检查清单（适用于 2Ryun 生成的网站）

> 用途：2Ryun 生成的网站上线前，逐项体检是否符合 GEO（生成式引擎优化）标准。
> 使用方式：自上而下逐项勾选（✅通过 / ⚠️需改善 / ❌缺失），每项给出"怎么查 / 通过标准"，最后汇总得分。
> 分级：🔴 P0（必须，阻塞上线） / 🟠 P1（强烈建议） / 🟢 P2（进阶，面向 AI Agent）

---

## 评分简表（填表先读这里）

| 维度 | 权重 | 本表得分 | 通过率 | 结论 |
|------|------|----------|--------|------|
| A 内容与信源 | 25% | __/__ | __% | 越全越好，缺失直接丢信源 |
| B 机器可读（抓取/结构/性能） | 25% | __/__ | __% | 是 GEO 地基 |
| C 结构化数据（Schema） | 20% | __/__ | __% | AI 引用精确性关键 |
| D 信任与可溯源 | 15% | __/__ | __% | 决定 AI 敢不敢引用 |
| E AI Agent 可消费 | 15% | __/__ | __% | 面向 Agent 自主调用 |

> 判定：A/B 有任一 ❌＝**存在阻塞项**；总体通过率 <70%＝不建议投放引流，先补齐再上线。

---

## A · 内容与信源（25%）


### A1 企业身份与定位（🔴 P0）
- [ ] 首页一句话讲清"我是谁、做什么、服务谁"（如"面向中小微企业的数智化服务商"）
- [ ] 公司主体信息完整可核验：法人/成立时间/注册资本/地址/联系方式
- [ ] 关键服务/业务用**用户能搜的词**描述，而非只有内部术语
- [ ] 有独立"关于我们"页，承载权威身份
- 怎么查：读首页首屏+关于页；把官网 URL 发给 AI"这家公司做什么"，看答得准不准
- 通过标准：AI 能在 1–3 句内说清你的定位与主业务，无错位/混淆

### A2 提问句式覆盖（🔴 P0）
- [ ] 核心业务覆盖"是什么 / 怎么做 / 在哪做 / 多少钱 / 和竞品区别"类提问句式
- [ ] 每张服务/主题页有 FAQ 或问答模块（自然语言问题→精炼答案）
- [ ] 答案**结论前置**：第一句直接给结论，再展开
- 怎么查：对照你的关键词，看页面是否以标题/问答形式命中用户问法
- 通过标准：一条问题一页/一个 FAQ 块；答案首句=答案

### A3 关键数据带出处与版本（🟠 P1）
- [ ] 能力/业绩数字（成立年限、客户数、案例）标注**时间戳或统计口径**
- [ ] 声明/数据能在站内或公开源**反查核验**
- 怎么查：找一处关键数字，Element 检视是否注明时间/口径
- 通过标准：任一关键数字可溯源，非凭空

### A4 原创性与不重复（🟠 P1）
- [ ] 全站无大面积重复/搬运文本（含对外与站点内互抄）
- [ ] 每页目标关键词不相互冲突打架
- 怎么查：抽查两三页正文相似度；看是否"一个站 N 个相似服务页"
- 通过标准：页面彼此区隔、均有独立价值

## B · 机器可读：抓取 / 结构 / 性能（25%）


### B1 基础协议文件（🔴 P0）
- [ ] `/robots.txt` 存在且非空，明确 AI 挖虫与全站抓取策略
- [ ] `/sitemap.xml` 存在，收录全部重要页（首页/关于/服务/案例/联系）
- [ ] ssitemap 中 URL 与 canonical 一致、无失效页
- 怎么查：浏览器访问 `域名/robots.txt`、`域名/sitemap.xml`
- 通过标准：两者 200 返回，非 404

### B2 每个页面元信息（🔴 P0）
- [ ] 每页有唯一且相关的 `<title>`
- [ ] 每页有唯一 `meta name="description"`（首页尤其不能空）
- [ ] h1 每页唯一，标题层级（h1→h2→h3）规范
- 怎么查：查看源码/用 SEO 插件扫全站
- 通过标准：无页面缺失 title/description；h1 唯一；首页 description 非空

### B3 正文可被解析（🔴 P0）
- [ ] 关键内容为**可见文本**，非纯图片/纯 JS 渲染
- [ ] AI 挖虫能读到正文（非"只有外壳、正文靠点击"）
- 怎么查：无头爬虫/`curl` 抓首页看是否含正文文本
- 通过标准：不执行 JS 也能拿到首页核心文本

### B4 规范与去重（🟠 P1）
- [ ] 重复/相似页有 canonical 指向主版本
- [ ] 无参数化无限重复 URL、无爬虫陷阱
- 怎么查：扫描重复 URL；检查分页/筛选是否被禁止抓取
- 通过标准：canonical 正确、无重复索引膨胀

### B5 性能基线（🟢 P2）
- [ ] 首页加载时间合理（移动端优先，越大越危险）
- [ ] 图片有懒加载/压缩、无超大阻塞资源
- 怎么查：Lighthouse/Search 面板性能分
- 通过标准：性能分数达标（视 2Ryun 模板基座）

## C · 结构化数据 Schema（20%）


### C1 组织与企业信息（🔴 P0）
- [ ] `Organization`（公司名/URL/logo/联系方式/地址）
- [ ] 服务业用 `ProfessionalService` 或 `Service`（业务主营+服务项目）
- 怎么查：页面右键"查看源代码"搜 `application/ld+json`
- 通过标准：存在合法 Organization；服务页有 Service

### C2 内容类型 Schema（🔴 P0）
- [ ] 文章/页面用 `Article`；问答用 `FAQPage`（Question/acceptedAnswer）
- [ ] 面包屑 `BreadcrumbList`；文章作者/日期标注
- 怎么查：对每个 FAQ/文章页查对应 JSON-LD
- 通过标准：FAQ 逐条 Question/acceptedAnswer 结构正确

### C3 数据合法性与校验（🔴 P0）
- [ ] `@id`/`@type`/`@context` 规范；URL 用绝对且 HTTPS
- [ ] 通过 **schema.org 校验器**（validator）无致命报错
- 怎么查：把 Schema 贴到 validator 检验
- 通过标准：校验通过、无红色错误

### C4 ID 稳定与去重（🟠 P1）
- [ ] 主体 `@id` 语义化且稳定（如 `/#organization`），多处引用不重复定义
- [ ] 同一页面主体用 `@graph` 聚合，避免互斥类型冲突
- 通过标准：Schema 无"重复定义/类型冲突"警告

---

## D · 信任与可溯源（15%）


### D1 信任基线（🔴 P0）
- [ ] 启用 HTTPS（非 http）
- [ ] 联系方式、地址、资质信息集中且各渠道一致
- 通过标准：全站 HTTPS；关键联系信息真实可见

### D2 时效与维护（🟠 P1）
- [ ] 关键页标注更新日期/版本
- [ ] 无过时信息仍挂在线（旧电话/旧地址/已下线业务）
- 通过标准：翻站无明显过期信息；数据带时间

### D3 口径一致性（🟠 P1）
- [ ] 官网数据与对外渠道（百科/企查查/第三方）**同一口径**，无打架
- [ ] 品牌名/域名表述统一，无张冠李戴
- 通过标准：抽查 3 个渠道，关键事实一致

### D4 站内口径澄清（🟢 P2）
- [ ] 若有同名公司/域名混淆，有专门澄清说明
- 通过标准：能搜到的"同名误会"在站内有纠偏

## E · AI Agent 可消费（15%）


### E1 LLMs.txt 体系（🟠 P1）
- [ ] `/llms.txt` 存在：企业定位 + 核心页索引（绝对 URL + 一句摘要）
- [ ] （可选）`llmsfull.txt` 附核心页全文、`llmshumans.txt` 人读版
- 怎么查：访问 `域名/llms.txt`
- 通过标准：200 返回、含定位与核心页链接

### E2 纯净正文与锚点（🟠 P1）
- [ ] 提供正文直取（`?output=plain` 或 `.md/.txt`）视图
- [ ] 关键段落有稳定 `id` 锚点，供 Agent 精确引用
- 怎么查：访问直取端点看是否为纯正文；检视是否有 id
- 通过标准：直取无导航/弹窗噪音；锚点可用

### E3 robots 的 AI 分级（🟠 P1）
- [ ] `/robots.txt` 显式声明主流 AI 挖虫（GPTBot/ClaudeBot/Google-Extended/Bingbot/Bytespider 等）
- [ ] 区分"允许抓取引用"与"禁训练/敏感目录禁抓"
- 通过标准：关键 AI 挖虫 Allow；敏感目录 Disallow

### E4 动态信息接口（🟢 P2）
- [ ] （如需实时报价/预约/库存）有结构化接口 + OpenAPI 描述，并登记进 llms.txt
- 通过标准：Agent 能经接口拿实时数据，而非解析 HTML

### E5 抓取与安全（🟢 P2）
- [ ] 增量抓取头 `ETag`/`Last-Modified` 支持 304
- [ ] 无提示注入/隐藏文本/内容污染面
- 通过标准：头有效；无可被诱导的隐藏内容
